# 信息系统实践课程Git简单教程

Git在这门课中主要用于：

- 保存项目过程
- 体现每位成员的实际贡献
- 统一管理代码、文档、测试材料
- 作为最终验收依据（以远端仓库为准）

注意：能计入成绩的工作，尽量都要在Git仓库中留下痕迹。建议小步提交、持续提交、代码和文档一起提交。

---

## 2. 最小指令集合

### 2.1 克隆仓库
```bash
git clone 仓库地址
```
第一次把远端仓库下载到本地，只需执行一次。

### 2.2 查看状态
```bash
git status
```
查看当前修改了哪些文件、哪些文件还没提交。

### 2.3 同步远端最新内容
```bash
git pull
```
每次开始工作前先执行，避免覆盖组员的修改。

### 2.4 添加修改
```bash
git add .
```
把当前改动加入待提交列表。

### 2.5 提交修改
```bash
git commit -m "本次修改说明"
```
提交说明要清晰、简单地写清楚本次提交的具体内容，不要只写 `update`、`fix`。如果修改说明跟提交内容没有关系，本次提交不计入考核分值中。

示例：
```bash
git commit -m "补充需求分析文档"
git commit -m "完成用户登录功能"
git commit -m "更新数据库表设计"
```

### 2.6 推送到远端
```bash
git push
```
把本地提交上传到远端仓库。

### 2.7 查看历史记录
```bash
git log --oneline
```
查看项目提交历史。

### 2.8 给阶段成果打标签
```bash
git tag v1-plan
git push origin v1-plan
```
建议按课程阶段打 tag，例如：

- `v1-plan`：计划书阶段
- `v2-design`：中期设计阶段
- `v3-final`：最终验收阶段

## 3. 最常用的工作流程

### 每次开始工作前
```bash
git pull
```
特别是同一个模块由超过1个同学合作开发时，这个很有必要。

### 完成一部分工作后
```bash
git status
git add .
git commit -m "本次修改说明"
git push
```
建议每次修改都做一次

### 阶段提交时
```bash
git add .
git commit -m "提交中期设计文档"
git push
git tag v2-design
git push origin v2-design
```

## 4. 非编码成员如何体现工作量

这门课里，以下工作都可以计入贡献：

- 需求分析
- 系统设计
- 数据库设计
- 测试设计与测试记录
- 文档撰写
- 项目管理与会议纪要
- 汇报材料整合

关键要求：**这些成果也要提交到Git仓库中。**

例如：

- 需求分析文档
- E-R 图、表结构设计
- 测试用例与测试记录
- 会议纪要、任务分解表、进度表
- PPT、说明书、部署说明

> 不是只有写代码才算贡献，关键是要在Git中留痕。

## 5. 建议的仓库目录

```text
docs/
  plan/
  design/
  test/
  meeting/
  report/

sql/
src/
ui/
```

说明：

- `docs/plan/`：项目计划书
- `docs/design/`：中期设计文档
- `docs/test/`：测试材料
- `docs/meeting/`：会议纪要、任务分解
- `docs/report/`：说明书、汇报材料
- `sql/`：数据库脚本
- `src/`：源码
- `ui/`：原型图、界面资源

---

## 6. 常见错误

- 长时间不提交，最后一天集中提交
- commit信息太随意
- 只commit不push
- 非编码工作不进仓库
- 只有一个人提交，其他成员没有记录
