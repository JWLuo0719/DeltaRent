# 后端接口需求文档 - 后台权限管理模块

> 本文档描述前端后台权限管理所需的接口需求，供后端开发参考。

---

## 一、用户管理

### 1. 用户列表（分页）
- **接口**: `GET /api/admin/users`
- **前端路径**: `src/web/src/views/admin/UserManageView.vue`
- **Query 参数**:
  - `page` (int, default: 1)
  - `pageSize` (int, default: 10)
  - `phone` (string, optional) - 按手机号搜索
  - `role` (string, optional) - 按角色筛选
  - `status` (int, optional) - 按状态筛选
- **响应**:
```json
{
  "success": true,
  "data": {
    "list": [
      {
        "id": 1,
        "phone": "13800000000",
        "nickname": "Admin Demo User",
        "role": "ADMIN",
        "status": 1,
        "createdAt": "2026-04-20T10:00:00Z"
      }
    ],
    "total": 100,
    "page": 1,
    "pageSize": 10
  }
}
```

---

### 2. 修改用户角色
- **接口**: `PUT /api/admin/users/:id/role`
- **前端路径**: `src/web/src/views/admin/UserManageView.vue`
- **请求体**:
```json
{
  "role": "CS"
}
```
- **响应**:
```json
{
  "success": true,
  "message": "角色已更新",
  "data": null
}
```
- **业务逻辑**:
  - 验证目标用户存在
  - 更新 `sys_user_role` 表
  - 记录操作日志

---

### 3. 禁用/启用用户
- **接口**: `PUT /api/admin/users/:id/status`
- **前端路径**: `src/web/src/views/admin/UserManageView.vue`
- **请求体**:
```json
{
  "status": 0
}
```
- **响应**:
```json
{
  "success": true,
  "message": "用户已禁用",
  "data": null
}
```

## 二、菜单权限

### 4. 获取当前角色的菜单
- **接口**: `GET /api/admin/menus`
- **前端路径**: `src/web/src/views/AdminDashboardView.vue`
- **响应**:
```json
{
  "success": true,
  "data": [
    {
      "key": "stats",
      "label": "数据看板",
      "icon": "📊",
      "roles": ["ADMIN"]
    },
    {
      "key": "users",
      "label": "用户管理",
      "icon": "👤",
      "roles": ["ADMIN"]
    },
    {
      "key": "products",
      "label": "账号管理",
      "icon": "🎮",
      "roles": ["ADMIN", "CS"]
    },
    {
      "key": "orders",
      "label": "订单管理",
      "icon": "📋",
      "roles": ["ADMIN", "CS"]
    },
    {
      "key": "notices",
      "label": "公告管理",
      "icon": "📢",
```

  - 不返回无权限的菜单项

## 五、TypeScript 类型定义（前端）

## 六、注意事项

1. **JWT 解析**: 所有 `/api/admin/*` 接口需要从 `Authorization: Bearer <token>` 中解析用户角色
2. **权限校验**: 后端需校验当前用户是否有权访问接口（如修改角色需 ADMIN）
3. **操作日志**: 用户角色变更、禁用启用等操作需记录到 `operation_log` 表
4. **角色枚举**: 目前系统预定义三种角色 `ADMIN(1)`, `CS(3)`, `USER(2)`，不可删除
5. **菜单联动**: 前端根据 `/api/admin/menus` 动态渲染菜单，不在前端硬编码
