# 前后端接口联调与后台管理改动说明 5.2

## 1. 这次改了什么

这次改动的目标是把项目里“看起来有页面、但后端还不完整”的部分补成真实可联调版本，重点覆盖两块：

1. 前台核心业务链路
2. 后台 4 个管理模块

已经完成的内容包括：

- 统一前后端接口契约，修复前端字段名和后端字段名不一致的问题
- 补齐认证、找回密码、个人资料、订单查询等真实后端接口
- 去掉前端若干页面中的 mock 数据，改为真实请求
- 补齐后台 `用户管理 / 角色管理 / 账号管理 / 公告管理`
- 调整测试和数据库脚本，使本地构建、测试、联调都能跑通

---

## 2. 改动背景

在这次改动之前，项目里有几个明显问题：

- 登录页前端发送的是 `phone + password`，后端最初按 `username + password` 处理
- 商品列表页、门户页、订单页需要的字段和后端返回结构不一致
- `订单列表`、`订单详情`、`个人资料`、`创建订单`、后台部分管理页仍然是 mock
- 后台菜单能进入某些页面，但后端权限没有完全对齐
- SQL 脚本、H2 初始化数据、当前后端实体定义之间有部分偏差

这次主要就是把这些“半联通状态”补成一套可以真实演示和继续开发的基础版本。

---

## 3. 前台相关改动

### 3.1 认证与用户

后端现在支持：

- `POST /api/auth/login`
- `POST /api/auth/register`
- `POST /api/auth/send-verify-code`
- `POST /api/auth/reset-password`
- `GET /api/users/me`
- `PUT /api/users/me`
- `PUT /api/users/me/password`

调整点：

- 登录兼容 `phone` 和 `username`
- 注册时默认给新用户分配 `USER` 角色
- JWT 里的角色不再写死为 `ADMIN`
- 个人资料页改为真实读取和保存
- 修改密码改为真实接口

### 3.2 商品与下单

后端现在支持：

- `GET /api/rentals`
- `GET /api/rentals/{id}`
- `POST /api/rentals`
- `PUT /api/rentals/{id}`
- `PUT /api/rentals/{id}/status`
- `DELETE /api/rentals/{id}`

其中前台使用的 `GET /api/rentals` 已补上这些筛选能力：

- `keyword`
- `status`
- `tags`
- `sortBy`

同时返回字段已经和前端页面统一，例如：

- `tagText`
- `hourPrice`
- `coinAmountText`
- `equipmentLevelText`
- `warehouseValueText`
- `description`

### 3.3 订单

后端现在支持：

- `POST /api/orders`
- `GET /api/orders/my`
- `GET /api/orders/{orderNo}`
- `PUT /api/orders/{orderNo}/cancel`
- `GET /api/orders`（后台）
- `PUT /api/orders/{id}/status`（后台）

前端已改为真实接口的页面：

- `src/web/src/views/OrderListView.vue`
- `src/web/src/views/OrderDetailView.vue`
- `src/web/src/views/ProfileView.vue`
- `src/web/src/views/RentalOrderCreateView.vue`

订单详情页现在按 `orderNo` 查，不再和前端路由冲突。

## 4. 后台 4 个模块的改动

### 4.1 用户管理

新增真实接口：

- `GET /api/admin/users`
- `PUT /api/admin/users/{id}/role`
- `PUT /api/admin/users/{id}/status`

功能：

- 分页查询用户
- 按手机号筛选
- 按角色筛选
- 按状态筛选
- 修改用户角色
- 启用/禁用用户

前端页面：

- `src/web/src/views/admin/UserManageView.vue`

### 4.2 角色管理

新增真实接口：

- `GET /api/admin/roles`
- `POST /api/admin/roles`
- `PUT /api/admin/roles/{roleCode}`

功能：

- 查询角色列表
- 新增角色
- 编辑角色名称和说明
- 返回每个角色的用户数量

前端页面：

- `src/web/src/views/admin/RoleManageView.vue`

说明：

- 这次给 `sys_role` 增加了 `description` 字段
- 初始化数据里补充了 `CS` 角色

### 4.3 账号管理

账号管理页不再是写死表格，已经接到真实 `rentals` 接口。

支持：

- 查询账号列表
- 新增账号
- 编辑账号
- 切换状态
- 删除账号

前端页面：

- `src/web/src/views/admin/ProductManageView.vue`

### 4.4 公告管理

公告相关后端原本已有基础 CRUD，这次主要完成了前端接入和权限对齐。

使用接口：

- `GET /api/notices/all`
- `POST /api/notices`
- `PUT /api/notices/{id}`
- `DELETE /api/notices/{id}`

支持：

- 查询全部公告
- 新增公告
- 编辑公告
- 显示/隐藏公告
- 删除公告

前端页面：

- `src/web/src/views/admin/NoticeManageView.vue`

## 5. 权限与菜单调整

这次补了几个权限对齐问题：

- 后台 `ADMIN` 仍然保留完整管理权限
- `CS` 现在和页面菜单一致，可以处理账号相关管理操作
- 公告管理的新增/编辑/删除只允许后台角色访问
- 后台首页增加了一个保护逻辑：如果当前角色没有默认菜单权限，会自动切到第一个可访问菜单

相关文件：

- `src/server/src/main/java/com/jwluo0719/deltatrade/config/SecurityConfig.java`
- `src/web/src/views/AdminDashboardView.vue`

## 10. 组员接下来阅读建议

如果要快速理解这次改动，建议按这个顺序看：

1. 先看前端接口封装：`src/web/src/api/index.ts`
2. 再看后端认证和订单：`AuthController / UserController / OrderController`
3. 再看后台新增接口：`AdminUserController / AdminRoleController`
4. 最后看四个后台页面的交互实现

如果你们后续要继续扩展，建议优先考虑：

- 把后台菜单也改为完全动态接口下发
- 给角色增加删除/权限点配置
- 给用户管理增加创建用户、重置密码
- 给账号管理增加图片、分页和更细的筛选
- 给公告管理增加创建时间、发布人等字段
