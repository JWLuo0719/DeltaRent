# 前后端接口联调与后台管理改动说明

本文档面向组员阅读，帮助大家快速理解这次“真实后端接口对齐 + 乱码治理”的主要变更。

## 1. 这次改了什么

这次改动的目标不是简单修几个接口，而是把仓库里已经更新过的前端页面、接口文档和 Spring Boot 后端真正对齐起来。主要完成了四件事：

1. 把核心前台链路改成真实可联调接口
2. 把验证码、密码重置、JWT 失效逻辑补成完整后端实现
3. 把租赁列表和下单接口收口到统一契约
4. 清理项目里遗留的中文乱码，补齐文档说明

## 2. 接口契约变更

### 2.1 租赁列表接口统一为对象响应

`GET /api/rentals` 以前存在“有时返回数组、有时返回对象”的过渡状态，现在已经统一为：

```json
{
  "success": true,
  "message": "ok",
  "data": {
    "list": [],
    "total": 0,
    "allTags": []
  }
}
```

已经支持的查询参数：

- `keyword`
- `tags`
- `level`
- `status`
- `sortBy`
- `page`
- `pageSize`

前端对应改动：

- `src/web/src/api/index.ts` 改成固定类型 `RentalListResult`
- `RentalListView.vue` 删除数组兼容分支
- `PortalView.vue` 改为读取 `data.list`
- `RentalOrderCreateView.vue` 改为读取 `data.list`
- `ProductManageView.vue` 改为读取 `data.list`

### 2.2 下单接口补齐防重复提交

`POST /api/orders` 现在增加了真实业务校验：

- 账号必须存在
- 账号必须是 `AVAILABLE`
- 同一用户 + 同一账号，只要已有 `WAITING_CONFIRM` 或 `IN_PROGRESS` 订单，就禁止再次提交

返回消息统一为：

- 成功：`订单已提交`
- 重复提交：`该账号已有进行中的订单，请勿重复提交`

## 3. 验证码落库与 JWT 失效策略

### 3.1 验证码不再只存在内存

新增表：

- `sms_verify_code`

主要字段：

- `phone`
- `code`
- `type`
- `expire_time`
- `created_at`
- `used_at`

当前行为：

- 发送验证码会真实落库
- 同手机号 60 秒内禁止重复发送
- 验证码有效期 10 分钟
- 当前仍是开发环境，短信发送是模拟的，验证码会打印在后端日志里

### 3.2 重置密码会使旧 token 失效

新增字段：

- `sys_user.password_updated_at`

JWT 现在会额外写入一个 `pwdUpdatedAt` 声明。后端过滤器在每次请求时都会比对：

- token 里的 `pwdUpdatedAt`
- 数据库里的 `password_updated_at`

只要用户修改过密码或重置过密码，这两个值就会不一致，旧 token 会立刻失效。

这个策略已经覆盖：

- `POST /api/auth/reset-password`
- `PUT /api/users/me/password`

## 4. 后台管理模块影响

后台已有的路径没有改动，重点是把返回文案、真实数据和前端行为对齐。

受影响模块：

- 用户管理
- 角色管理
- 账号管理
- 数据看板
- 订单管理

其中还顺手修复了后台接口中残留的乱码中文，例如：

- 角色创建成功
- 角色已更新
- 用户状态已更新
- 状态更新成功

## 5. 乱码修复范围

这次按“全仓库清理”的要求处理了编码问题，重点包括：

- 后端控制器和服务中的中文提示语
- 种子数据和 SQL 中的中文文本
- 前端部分页面提示语
- `docs/api/后端接口文档.md`
- 本说明文档

当前结论：

- 用户可见文案已统一为正常 UTF-8 中文
- 接口错误消息不再出现乱码
- H2 种子数据中的中文账号、公告内容也已恢复正常

## 7. 组员接手建议

如果你要继续开发，建议按这个顺序看：

1. 先看接口文档 `docs/api/后端接口文档.md`
2. 再看认证相关 `AuthController / UserService / JwtAuthFilter / JwtUtil`
3. 再看租赁与订单 `RentalController / ProductService / OrderController / OrderService`
4. 最后看前端 `RentalListView.vue` 和 `src/web/src/api/index.ts`

如果后续继续扩展，优先建议：

- 把后台账号管理补上分页
- 给验证码发送增加 IP 维度限流
- 给订单增加更明确的支付/交付状态
- 给后台订单页补充状态修改操作和分页
